---
name: share-skill
description: 当同事说“把这个做法做成技能分享给大家”、想分享刚完成的工作方法，或更新自己已分享的技能时使用。把对话里的做法提炼为可复用技能，作者自测确认后提交技能市场审批。
---

从当前对话提炼真正有效的步骤、模板和注意事项。只保留换一个同事或客户仍适用的内容。把具体客户、金额、人名、内部地址和本机路径换成有含义的占位说明；不要把凭据写进技能或附件。没有足够的工作过程可提炼时，先和作者澄清要分享的做法。

为技能起一个简短的小写英文连字符名称。先运行 `wp-market list` 核对名称；不要覆盖预装技能、官方保留名称或别人的技能。更新已有技能时沿用自己的名称。

在本人 `~/.wp-skill-uploads` 内创建临时目录，生成 `SKILL.md`，frontmatter 含 `name` 与中文 `description`，description 说明什么时候用。需要模板或脚本时把它们放进同一个目录并打成 zip；没有附件时只用 Markdown。用 `wp-skill install <文件>` 装到本人名下，只有作者同意替换已有版本时才加 `--overwrite`。检查命令返回的 JSON，出现 error 表示未完成。

先请作者开一个新的网页对话试一次；使用飞书个人智能体时发 `/new` 开始新话题测试。测试后回到原对话，明确确认是否分享。此时结束当前工作，不自行提交。作者确认分享后，从本人技能目录读取最终自测版本，准备中文名、一句话说明和一个真实可用的例句；执行：

```sh
wp-market submit <技能名> --title '<中文名>' --description '<一句话说明>' --example '<例句>'
```

命令使用本人容器身份，与网页上传共用提交接口。不要读取或展示身份文件。只有返回 `status: pending` 才说已提交等待 IT 审批，审批结果会通过飞书通知；`reviewNotice: failed` 表示审批卡片未送达，明确告知作者可在市场查看进度，不重复提交。被扫描拦下时，去掉具体信息并重新自测。已经上架的技能更新后仍须作者确认并重新审批，审批前其他人继续用上一已批准版本。
