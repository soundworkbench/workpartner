## 必改（安全审查高）：`gateway/services.mjs` 内部监听器无异常兜底
`listen()` 里 `internal = http.createServer(async (req, res) => { if (await desktopMcp?.(req, res, new URL(req.url, 'http://gateway.internal'))) return; ... })`：
- `desktop.enabled=true` 时 `desktopMcp` 存在，每个请求都先执行 `new URL(req.url, ...)`；畸形请求目标（如 `GET //[ HTTP/1.1`）会抛 `Invalid URL`。以前 Docker 无 dataTools 时 `dataTools?.()` 短路不求值，所以这是本分支引入的。
- 异步处理函数抛错变成 unhandled rejection，网关没有 `unhandledRejection` 处理，Node 默认终止进程，所有用户的网关、桌面中继一起断。任何能连内部端口的对端（包括用户容器）都能触发。

要求：
1. 在内部处理函数里先 `try { const url = new URL(req.url, 'http://gateway.internal'); ... } catch { ... }`：URL 解析失败回 400；其他处理器抛错回 500（已发头则直接 end / destroy），不回显错误细节，只记路由名和错误码一行日志。解析好的 `url` 传给 desktopMcp、dataTools、extension.internal，不再各自重复 new URL。
2. 原有各处理器的顺序和行为不变。
3. 补回归测试：对内部端口发畸形请求目标（用原始 socket 写 `GET //[ HTTP/1.1\r\nHost: x\r\n\r\n`）应得到 400（若 Node 解析器先行拒绝、回 400 或断开也可，测试里如实断言实际行为），且之后正常请求仍能得到响应、进程未退出；再测一个处理器抛错时回 500 且进程存活。
4. 顺带检查 `gateway/gateway.mjs` 主 `server` 的 `upgrade` 新增分支里的 `new URL(req.url, 'http://gateway')` 是否在 try 内；不在就挪进去。
