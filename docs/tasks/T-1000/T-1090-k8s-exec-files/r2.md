注意：K1 已合入 main，`gateway/runtime/kube-client.mjs` 里 exec 的 timeoutMs / connectTimeoutMs 经 duration() 校验，0 不是“不限时”。

1. 租约持有进程无存活上限（k8s-files.mjs:121-137）：网关在 putFiles 后、removeFiles 前崩溃时进程永远留在容器里每 25ms 轮询。给持有进程设存活上限（可配，缺省如 30 分钟），到时自行清理暂存内容和控制目录后退出；轮询间隔放宽到合理值（如 200ms）。
2. 持有进程被 SIGKILL 后 removeFiles 永远失败（k8s-files.mjs:38-49、272-274）：释放失败时退回按路径删除暂存内容和控制目录，并把租约标记为已释放；不能让 market-skills.mjs:25 finally 里的调用把成功安装盖成失败。
3. timeout/createTimeout 为 0（k8s-exec.mjs:30、42-44）：Docker 版 0 表示不限时（onboard.mjs:67 传 0）。K1 不接受 0；改为 0 时映射到一个有上限的长时限（如 24 小时，常量写清含义），不要原样传 0。
4. k8s-files.mjs:271-272 先 patch Secret 再释放租约，两步间加 try/finally；237-239 失败时补做的 release 若再抛错，不得盖掉原始错误（原错误优先，补救错误附在 cause 或丢弃）。
5. 主容器名 `workspace`（k8s-exec.mjs:28）与 K2a 实现一致（k8s.mjs 用的也是 workspace），保留；在报告“对其他 K 任务的接口假设”里写明。
6. 测试里的 example.com（tools/runtime-k8s-files.test.mjs:166、184-185）改成 `*.test` / `*.invalid` 域名。
7. 普通文件 readFile 经 exec 读取时设 maxOutputBytes 上限（与 Docker 版读文件上限一致；没有则取合理常量并写明）。
8. 知道了项中：readFile 读到目录时报 EINVAL，Docker 版是 EISDIR —— 改成 EISDIR 保持一致。
