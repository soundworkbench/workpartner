### 必改
1. **verify 的网关 exec 容器名错误**（adopt-user.mjs:173）：K2a `execNamed` 用 `systemContainer ?? Pod 名` 作容器名，网关 Deployment 的容器名固定是 `gateway`。网关探测要单独用带 `systemContainer: 'gateway'` 的运行时实例（或从 Pod spec 取名为 gateway 的容器），不要改全局配置。测试的假 execNamed 要断言目标容器名，并加一条接真实 `createRuntime`（K2a）装配、只替换 K1 客户端的用例。
2. **PV 重跑误判冲突**（adopt-user.mjs:216、:228；adopt-state.mjs:59-63）：API 会省略空的 `storageClassName`，比较时把缺失视作 `""`；对 API 可能省略的空值、额外的 apiVersion/kind、claimRef.uid/kind 等做归一后再比较。补用例：假 GET 去掉空 storageClassName、加 apiVersion/kind/claimRef.uid，pv 可以重跑并保留匹配对象。
3. **switch 发现重复实例后状态不安全**（adopt-user.mjs:282-287）：结束时归属必须和保留的实例一致。按「保留 Docker」：确认 Pod 消失（且 StatefulSet replicas=0）后，把归属原子写回 docker；NEXT 文案与最终状态一致。补用例断言最终归属。
4. **启动另一端前没核对 StatefulSet replicas**（adopt-user.mjs:120、:306、:330-333）：rollback 在 `docker start` 前要求 inspect 满足「不存在或 replicas === 0」且没有任何 Pod；switch 在 runtime.start 前再读一次归属文件确认仍是 k8s、Docker 不活跃。补对应用例（模拟中途 replicas 被改回 1 时拒绝启动）。
