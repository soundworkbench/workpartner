# T-1190 第 3 轮返工：修浏览器测试在 390/360 宽度的误报

原任务说明：docs/tasks/T-1100/T-1190-voice-mic-placement/brief.md；上一轮返工：同目录 r2.md。验收标准不变。

## 现状
GitHub Actions「Browser tests」的 voice 组：1280 通过；390、360 两个用例失败，都在 tools/browser-tests/voice.e2e.mjs 约第 407 行（加了 transition clone 之后的那次 placement()）：
  actual:   { overflow: true,  overlap: false, inside: true, modelBefore: true, zeroMargin: true }
  expected: { overflow: false, ... }
之前所有 placement() 都通过，截图里话筒位置正确（输入框右、发送左，模型在下一行/话筒左边）。

## 根因（协调者判断，请先核实）
测试把 `#voice-composer` 克隆一份、`clone.id = ''` 后 append 到 body 模拟过渡克隆。夹具 CSS（tools/browser-tests/lib/site.mjs 约 140-157 行）全部以 `#voice-composer` 为前缀，克隆体丢了 id 就没有任何布局样式（textarea 80px 高无宽度约束、flex 失效等），在手机宽度下把页面撑出横向滚动。这是夹具问题，不是产品问题。

## 要改
- 让过渡克隆在布局上和原输入框一致或不参与页面宽度：例如给克隆保留同样的布局样式（把夹具 CSS 选择器改成同时匹配 `#voice-composer, .wp-transition-composer`，或给克隆加 `position:fixed; left:0; right:0; max-width:100vw; visibility:hidden; pointer-events:none` 之类）。选最贴近真实 AionUI 过渡克隆的做法，在报告里说明。
- 不要放宽或删掉 overflow 断言；不要改 gateway/voice-client.mjs。
- 确认 390/360 的 home 截图（`390-home.png`、`360-home.png`）在用例通过后能生成。

- 浏览器 E2E 以 GitHub Actions 为准，本地不用跑。
