1. `gateway/tests/voice.test.mjs:71`：`f.request({ method: 'GET' })` 用了默认的 `body = Buffer.from('audio-private')`。GET 请求不分块也不带 Content-Length，请求体以裸字节写进 keep-alive 连接，把连接弄脏，紧接着第 72 行的 403 请求必定 `ECONNRESET`。Node 22/24 都能稳定复现，`tools/check.sh` 会因此失败。

## 本轮一起做的建议
2. `gateway/voice-client.mjs:174-195`：按住说话时按钮被移出 DOM 或重建，指针捕获丢失，`press` 一直不清空，之后按钮点了没反应。监听 `lostpointercapture` 走取消流程；另外在 pointerdown 里发现 `press.button` 已不在页面中时先清掉旧状态。补单测或浏览器断言。
3. `gateway/voice-client.mjs:124`：识别期间 textarea 被重渲染替换时，结果被静默丢弃。改为按同一 selector 找当前可见的输入框插入；找不到时给一条提示，不要静默丢。
4. `gateway/voice-client.mjs:222`：MutationObserver 每次变化都同步跑完整 `mount()`（里面有强制重排）。用 requestAnimationFrame 合并成每帧最多一次，并照 `gateway/my-key-client.mjs:26` 的 `safe()` 写法包一层，避免反复报页面错误。
5. 录音中的红色不要写死 `#d92d20`：定义一个带回退值的变量，例如 `var(--wp-danger, #d92d20)`。
6. `gateway/voice.mjs:75`：30 秒总截止时间要同时覆盖读请求体阶段，不只是上游调用。网关先在截止时间内完整收下请求体（仍按 2 MiB 上限），收完再转发给识别服务；超时返回 408 或已有的超时错误码，名额照常释放。识别服务那边并发名额在读体期间一直占着，所以网关必须先收完再转发。补单测（慢速上传超时、名额释放）。
7. `gateway/tests/voice-client.test.mjs:43`：不要按源码文本截取函数片段塞进 vm 运行。把需要测的纯函数（WAV 编码、重采样、录音状态机里可以独立出来的部分）正式导出后再测；录音生命周期交给浏览器测试覆盖。
8. 识别服务（T-1184）忙时返回 503 且正文一定是 JSON `{"error":"busy"}`，保持现有映射即可（503+JSON busy → busy，非 JSON → unavailable），不用改。
