## 必改
1. `gateway/feishu-bot.mjs:10` 用 `JSON.parse(result.logs)` 解析结果，但 `gateway/runtime/docker.mjs:43-57` 的 `logs` 是 stdout 和 stderr 交错拼在一起的。容器里脚本只要往 stderr 写一点东西，就会出现两个问题：
   - `/bots` 和 `/reconnect` 返回 503；
   - onboarding 的 restart 明明成功了，也会回退去重启整个容器。

   要做的：
   - 改成解析 `result.stdout`。docker 和 k8s 两个 runtime 的 exec 结果都核对一下有这个字段；没有的话，在不改 runtime 行为的前提下想办法拿到纯 stdout，并在汇报里说明。
   - 补单测：stdout 是合法 JSON、stderr 有杂讯时，接口返回 200，onboarding 不调 `runtime.restart`。

## 本轮一起做的建议
2. 浏览器测试 `tools/browser-tests/feishu-bot.e2e.mjs:45` 的首页溢出断言测不出问题，因为测试页 `<main>` 是 `overflow:hidden`（`lib/site.mjs:83`）。在 390 和 360 宽度下改成断言两件事：
   - `.wp-feishu-bot-bar` 的 `scrollWidth <= clientWidth`；
   - 条内每个按钮和链接的 `getBoundingClientRect().right <= innerWidth`。
3. `feishu-bot.mjs:8` 的 exec 加输出上限（比如 `maxOutputBytes` 1MB，看 runtime 支持的参数名），超了按 503 处理。
4. `feishu-bot.mjs:55-56` 的名单判断加上 `user.backend === 'aionui'`，和 `feishu-onboarding.mjs:68` 一致。clientFor 也一样，非 aionui 用户不下发脚本。补测试。
5. 菜单分隔线：现在的顺序会变成「…原有项, 我的飞书机器人, 分隔线, 我的钥匙, 退出」，飞书这一项和原有项之间没有分隔线。参照 `my-key-client.mjs:66-72`，让「我的飞书机器人」和「我的钥匙」归在同一组，和原有项之间有分隔线，而且不管两个功能各自开不开，分隔线都不会重复、不会缺。浏览器测试加一条断言。
6. `feishu-bot.mjs:83` 的 reconnect 按用户做并发合并，和 info 一样：同时多次点击只执行一次 restart。补测试。
7. onboarding 里 `restart` 的 exec 超时从 10 秒放宽到 20 秒。镜像侧 restart 只是写一个 FIFO 通知就返回，正常很快；放宽是为了避免偶发的慢，造成误回退去重启容器。
